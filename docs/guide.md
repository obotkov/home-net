# Как работать с админкой

## Как устроена сеть

```
  телефон/ноутбук снаружи                       дом (192.168.1.0/24)
        │ VLESS (приложение)                   ┌──────────────────────────┐
        ▼                                      │  роутер 192.168.1.1      │
   ┌─────────┐  Xray → WireGuard → OSPF        │                          │
   │ VPS ams │◀──────────────────────────────▶ │  узел netadmin  (.20)    │──┐
   └─────────┘                                 │  GPU-ПК         (.10)    │  │ LAN
   ┌─────────┐                                 │  NAS, виртуалки (.11…)   │◀─┘
   │ VPS hel │◀──────────────────────────────▶ └──────────────────────────┘
   └─────────┘
```

В сети три вида участников, и добавляются они по-разному:

| Кто | Что ставить | Где добавлять |
|---|---|---|
| **Узел netadmin** (мини-ПК, Raspberry Pi, сервер дома) | `install.sh` | один на дом, ставится первым |
| **VPS** (точки входа снаружи) | ничего руками, админка ставит сама по SSH | вкладка «VPS» |
| **Домашние компы, NAS, виртуалки** | **ничего** | появляются сами во вкладке «Устройства» |
| **Телефон / ноутбук снаружи** | приложение v2rayNG / Hiddify / Streisand | ссылка «Доступ с телефона» в карточке VPS |

Главное: на домашние компьютеры и виртуалки ничего ставить не нужно. Они доступны снаружи через узел netadmin,
который маршрутизирует трафик из туннелей в домашнюю сеть.

## 1. Первый запуск

1. Поставьте админку на всегда включённую Linux-машину дома: `curl -fsSL https://raw.githubusercontent.com/obotkov/home-net/main/install.sh | sudo bash`.
2. Откройте адрес, который напечатал скрипт, логин `admin`, пароль из вывода (он же в `/etc/netadmin.env`).
3. Вкладка **Настройки**: проверьте LAN-интерфейс (например `eth0`) и подсеть (`192.168.1.0/24`). Именно эту подсеть
   узел объявит по OSPF, и именно она будет доступна снаружи.
4. Скопируйте SSH-ключ, который напечатал скрипт: он понадобится для VPS.

## 2. Добавить VPS

Подойдёт любой VPS на Debian 12 / Ubuntu 22.04+ с белым IP, лучше чистый.

1. Вход на VPS: **по паролю** или **по ключу**, как удобнее.
   - По паролю: просто впишите пароль в поле «SSH пароль» формы (или в окне «Развернуть»). Админка один раз
     войдёт по паролю, поставит на VPS SSH-ключ узла и дальше будет ходить по ключу. Пароль не сохраняется.
     Если пользователь не root, тот же пароль используется для `sudo`.
   - По ключу: `sudo ssh-copy-id -i /root/.ssh/id_ed25519 root@<IP VPS>` с узла netadmin
     или вставьте ключ в `~/.ssh/authorized_keys` на VPS через панель хостера. Тогда поле пароля оставьте пустым.
2. Вкладка **VPS** → форма «Добавить VPS»:
   - **Имя**: латиница, коротко (`ams`, `hel`). Из него получится интерфейс `wg-ams`.
   - **Публичный IP** VPS.
   - **Порт Xray**: 443, если на VPS больше ничего не слушает этот порт.
   - **SNI**: сайт, под который маскируется трафик, по умолчанию `www.microsoft.com`, можно оставить.
   - **Стоимость OSPF**: чем меньше, тем предпочтительнее этот VPS, если их несколько (10 — основной, 20 — запасной).
3. Если указали пароль в форме, развёртывание начнётся сразу. Иначе нажмите на карточке **«Развернуть по SSH»**. Админка поставит на VPS WireGuard, Xray, BIRD, запишет конфиги,
   закроет порт WireGuard снаружи. Ход виден в «Логе развёртывания».
   Без SSH-ключа: «Конфиги» → `bootstrap.sh`, и на VPS `sudo bash bootstrap.sh`.
4. Нажмите **«Применить дома»** (вверху вкладки VPS). Дома поднимется интерфейс `wg-ams`, Xray получит маршрут до VPS,
   BIRD — новый линк.
5. Через минуту на **Обзоре** линк станет зелёным, во вкладке **Маршруты** появится OSPF-сосед в состоянии `Full/PtP`.

Второй, третий VPS добавляются так же. Каждый — отдельный линк до дома, OSPF сам выберет лучший и переключится,
если один упадёт.

**Удалить VPS**: «Удалить» на карточке, затем «Применить дома» (интерфейс уберётся). На самом VPS сервисы
останутся, VPS можно просто удалить у хостера.

## 3. Подключить телефон или ноутбук снаружи

1. Карточка VPS → **«Доступ с телефона»** → «Копировать ссылку» (`vless://…`).
2. Поставьте клиент: **v2rayNG** или **Hiddify** (Android), **Streisand** или **FoXray** (iOS),
   **v2rayN** или **Hiddify** (Windows / macOS / Linux).
3. В клиенте: «Импорт из буфера» → подключиться.
4. Теперь из любой сети открываются домашние адреса: `192.168.1.10`, NAS, роутер. Интернет при этом идёт через VPS.

Одна ссылка на VPS, её можно импортировать на все свои устройства. Если ссылка утекла, удалите VPS и добавьте заново:
ключи сгенерируются новые.

## 4. Домашние компьютеры, NAS, виртуалки

**Ничего добавлять не нужно.** Всё, что подключено к домашней сети, видно во вкладке **Устройства**
(по ARP и DHCP-арендам) и доступно снаружи по своему LAN-адресу.

Чтобы было удобно:

- **Закрепите адреса.** На роутере в DHCP сделайте резервирование (static lease) для GPU-ПК, NAS, серверов,
  чтобы их IP не менялся. Имя в «Устройствах» берётся из DHCP, поэтому задайте компьютеру понятное имя хоста.
- **Виртуалки — в режиме моста (bridge)**, а не NAT. Тогда у ВМ свой адрес из домашней сети, она появится
  в «Устройствах» и будет доступна снаружи как обычный компьютер.
  - VirtualBox: Сеть → «Сетевой мост».
  - Hyper-V: внешний виртуальный коммутатор.
  - Proxmox: `vmbr0` (по умолчанию уже мост).
  - libvirt/virt-manager: мост `br0` вместо `default` (NAT 192.168.122.0/24).
  ВМ за NAT снаружи не видны: до них можно достучаться только пробросом порта на хост-машине.
- **Фаервол на компах.** Узел netadmin подменяет адрес источника на свой LAN-адрес (masquerade), поэтому для
  компьютеров соединение снаружи выглядит как обычное из домашней сети, особых правил не нужно.
  Если RDP/SSH не пускает даже из дома, проблема в настройках самого компа.

## 5. GPU-ПК снаружи

| Задача | Как подключаться |
|---|---|
| Игры, рабочий стол с минимальной задержкой | **Sunshine** на ПК + **Moonlight** на клиенте, адрес `192.168.1.10` |
| Обычный удалённый рабочий стол (Windows) | RDP: включить «Удалённый рабочий стол», подключаться к `192.168.1.10` |
| ML, вычисления, Jupyter | SSH / VS Code Remote-SSH на `192.168.1.10`, Jupyter через `ssh -L 8888:localhost:8888` |
| Включить выключенный ПК | Wake-on-LAN: на узле netadmin `sudo apt install wakeonlan`, затем `wakeonlan <MAC>` (MAC — во вкладке «Устройства») |

Для Wake-on-LAN включите WoL в BIOS и в свойствах сетевой карты, ПК должен быть подключён кабелем.
Учтите, что VLESS идёт поверх TCP: для Moonlight при плохой связи возможны рывки, для RDP и SSH это незаметно.

## 6. Как понять, что всё работает

- **Обзор**: зелёный линк — есть handshake WireGuard и OSPF-сосед. Жёлтый — что-то одно. Красный — нет связи.
- **Маршруты**: сосед `Full/PtP` на каждом VPS.
- С телефона через VPN: `ping 192.168.1.1` (роутер) — пинг есть, значит вся цепочка работает.

Если линк красный:
1. Лог развёртывания VPS: нет ли ошибок.
2. На узле: `sudo wg show` (есть ли `latest handshake`), `sudo systemctl status xray`, `sudo birdc show ospf neighbors`.
3. На VPS: `systemctl status xray wg-quick@wg-home bird`.

## 7. Обновления

**Настройки → Обновления**: видно установленную версию (коммит), кнопка **«Проверить»** сравнивает её с `main`
на GitHub и показывает список изменений. Кнопка **«Обновить»** скачивает свежий `install.sh` и запускает его
без вопросов: код заменяется, ключи, VPS и настройки домена сохраняются, панель перезапускается и страница
перезагрузится сама. Ход обновления виден в журнале под кнопкой (он же в `/var/lib/netadmin/update.log`).
Когда есть обновление, у вкладки «Настройки» появляется точка.

То же самое руками: запустить команду установки ещё раз.

## 8. Вход по passkey

Passkey — вход по отпечатку, Face ID, Windows Hello или аппаратному ключу (YubiKey) вместо пароля.

1. Откройте панель **по домену через HTTPS** (passkey не работает по `http://IP`, это ограничение браузеров).
2. Войдите паролем → **Настройки → Passkey → «Добавить passkey»**, дайте название («iPhone», «Ноутбук»).
3. Теперь на странице входа достаточно нажать **«Войти с passkey»**.

Можно добавить несколько passkey (телефон, ноутбук, ключ). Пароль остаётся запасным способом входа.
Passkey привязан к домену: если домен поменяется, passkey нужно добавить заново.

## 9. Режим «панель на VPS + Keenetic»

Если дома нет Linux-машины, входом в домашнюю сеть может быть роутер Keenetic (KeeneticOS 4.2+ / 5.x).
Панель ставится на VPS, а роутер сам держит туннель WireGuard с обфускацией ASC (AmneziaWG) до каждого VPS.
Ни флешка, ни Xray, ни OSPF на роутере не нужны.

```
 телефон ── VLESS ──▶ VPS (панель, Xray, AmneziaWG) ◀── AmneziaWG ── Keenetic ── домашняя сеть
```

1. Поставьте панель на VPS той же командой `install.sh`.
2. **Настройки → «Вход в домашнюю сеть» → «Роутер Keenetic»**, проверьте LAN-подсеть (как в Keenetic, например
   `192.168.1.0/24`), сохраните.
3. **VPS → «Установить AmneziaWG и Xray на этот сервер»**. Панель сама определит IP, выберет порт Xray
   (443 или 8443, если 443 занят HTTPS панели) и поставит всё локально, без SSH. Другие VPS добавляются формой
   «Добавить VPS».
4. На карточке VPS нажмите **«Keenetic»**:
   - скачайте `keenetic-<имя>.conf` и импортируйте в Keenetic: **Интернет → Другие подключения → WireGuard →
     «Загрузить из файла»**;
   - в подключении снимите «Использовать для выхода в интернет» и включите его;
   - в командной строке роутера (`http://my.keenetic.net/a`) выполните команды из окна. Они разрешают доступ из туннеля
     в домашнюю сеть (`security-level private`) и задают параметры ASC.
5. Телефоны подключаются как раньше: ссылка «Доступ с телефона» на карточке VPS.

**Второй VPS для резерва.** Добавьте его так же и импортируйте его конфиг в Keenetic вторым подключением.
У каждого VPS свой туннель до роутера, телефону достаточно переключиться на ссылку другого VPS.
Если упадёт VPS с панелью, туннели и доступ через второй VPS продолжат работать, недоступна будет только панель.

Статус туннеля в панели виден для того VPS, на котором стоит панель. Для остальных VPS статус «не видно отсюда»,
проверить можно в Keenetic (подключение WireGuard, «Последнее рукопожатие»). Вкладки «Устройства» и «Маршруты»
в этом режиме скрыты: домашнюю сеть видит роутер, а не VPS.

## 10. Вкладка «Сервер»

Состояние служб на сервере, где стоит панель: Xray, туннели WireGuard / AmneziaWG (и BIRD в режиме Linux-узла).

- **Службы**: работает ли служба, сколько времени, PID, память, число перезапусков. Кнопки «Журнал»
  (последние 40 строк `journalctl`) и «Перезапустить».
- **Xray**: версия, входы (порт и слушает ли он, REALITY, SNI, клиенты), выходы, конфиг с скрытыми секретами.
- **WireGuard / AmneziaWG**: адрес туннеля, порт, публичный ключ, параметры обфускации ASC, реализация
  (модуль ядра или amneziawg-go) и пиры: endpoint роутера, последнее рукопожатие, трафик.

Данные обновляются каждые 5 секунд, пока вкладка открыта.
